Problem

Automated logins driven by the agent (today: the agent-browser NetSuite session) stall whenever NetSuite asks for a 6-digit TOTP code, because the only authenticator is on Jon's phone. The todo asks for a CLI that stores a TOTP secret under a name and later prints the current code for that name, so the agent can answer the 2FA prompt itself.

Decisions already made with Jon

Purpose: primarily unattended use by the agent (NetSuite 2FA); also fine to run by hand.
Language: Rust, following netsuite-cli / intacct-cli / clickup-cli conventions.
Secret store: the OS credential store via the keyring crate — macOS Keychain and Windows Credential Manager. Both must work; the tool is not macOS-only.
Repo: totp-cli, public, under the CreativePlanningBusinessServices GitHub org, in ~/projects/creativeplanning/totp-cli. GitHub repo is created only after Jon approves this spec and the plan.
v1 scope: add (bare secret or otpauth URI), code, list, remove, --json, plus update and skill install like the sibling CLIs.
Follow-up: once released, change the NetSuite section of ~/.claude/CLAUDE.md so the agent fetches the code with totp-cli instead of asking Jon.

Command surface

totp-cli add <name> [--secret <BASE32> | --uri <otpauth://...>]
                    [--digits 6] [--period 30] [--algorithm sha1|sha256|sha512]
                    [--issuer <text>] [--force]
totp-cli code <name> [--min-remaining <secs>]
totp-cli list
totp-cli remove <name>
totp-cli skill install
totp-cli update [--check]

global: --json, --version, --help

add

  • <name> is the local alias: 1–64 chars from [A-Za-z0-9._-], case-sensitive. Anything else is a usage error.
  • Exactly one source of the secret: --secret, --uri, or neither. With neither, the secret is read from the terminal without echo (rpassword) so it stays out of shell history. Passing both is a usage error.
  • --uri accepts the otpauth://totp/... URI behind a QR code and takes secret, issuer, digits, period and algorithm from it. Explicit flags override URI values. otpauth://hotp/ is rejected.
  • Base32 secrets are normalised before storage: uppercase, whitespace and - removed, padding optional. A secret that does not decode is a usage error.
  • Defaults: 6 digits, 30-second period, SHA-1. Allowed digits: 6–8. Period must be ≥ 1.
  • If the name already exists, fail unless --force, which replaces both the secret and the index entry.
  • Order of writes: secret into the credential store first, then the index file. If the index write fails, the just-written secret is deleted again so the two never disagree.
  • Human output: added netsuite. JSON: {"name":"netsuite","issuer":"NetSuite","digits":6,"period":30,"algorithm":"sha1"}. The secret is never echoed.

code

  • Prints the current code and a newline, nothing else: 123456. Codes are zero-padded to digits.
  • --min-remaining <secs>: if the current code expires in fewer than that many seconds, sleep until the next period starts and print that code instead. Default 0 (never wait). This stops an automated login from submitting a code that rolls over while the form is being filled.
  • JSON: {"name":"netsuite","code":"123456","expires_in":17,"period":30}.
  • Hidden --at <unix-seconds> flag computes the code for a fixed time. Used by the integration tests and for debugging clock skew; not shown in --help.
  • Unknown name → exit 2. Name present in the index but secret missing from the store → exit 3 with a message suggesting add --force.

list

  • Human: one name per line, sorted, from the index file only. The credential store is not touched.
  • JSON: array of {"name","issuer","digits","period","algorithm"}. Never includes secrets.

remove

  • Deletes the credential-store entry, then the index entry. A missing store entry is not an error, so a half-removed account can always be cleaned up.
  • Unknown name → exit 2.

skill install and update

Same behaviour as netsuite-cli: skill install writes the embedded SKILL.md to $CLAUDE_CONFIG_DIR or ~/.claude under skills/totp-cli/SKILL.md, skipping a symlinked or identical copy. update uses self_update against GitHub Releases of CreativePlanningBusinessServices/totp-cli, then refreshes the skill. update --check only reports.

Storage

Secrets: OS credential store

PlatformBackendNotes
macOSKeychain via keyring feature apple-nativeService totp-cli, account = name. First access by a new binary build may show one keychain dialog; "Always Allow" makes later reads unattended.
WindowsCredential Manager via keyring feature windows-nativeGeneric credential keyed on totp-cli + name. Credential Manager caps blobs at 2560 bytes, far above any TOTP secret, so no chunking.
Linux / CIFile store (below)No credential-store features are enabled for Linux, so the OS backend is unavailable there; TOTP_CLI_SECRET_STORE=file is required.

Only the base32 secret goes in the credential store. Everything else lives in the index file, because the keyring crate cannot enumerate entries and list needs to.

Index: accounts.toml

[accounts.netsuite]
issuer = "NetSuite"
digits = 6
period = 30
algorithm = "sha1"

Location is the directories config dir for ProjectDirs::from("com", "CreativePlanning", "totp-cli"): ~/Library/Application Support/com.CreativePlanning.totp-cli/ on macOS, %APPDATA%\CreativePlanning\totp-cli\config\ on Windows, ~/.config/totp-cli/ on Linux. TOTP_CLI_CONFIG_DIR overrides it. The file is written atomically (temp file + rename) and created with mode 0600 on Unix.

Test / fallback file store

TOTP_CLI_SECRET_STORE=file swaps the credential store for secrets.toml in the config dir (0600 on Unix). It exists so the test suite and Linux CI never touch a real keychain, and as an escape hatch for headless Linux hosts. The README labels it as unencrypted at rest.

TOTP core

  • RFC 4226 HOTP + RFC 6238 TOTP implemented directly with the hmac, sha1 and sha2 crates. Roughly 40 lines; no totp-rs dependency.
  • Counter = floor(unix_time / period); dynamic truncation; code = value mod 10^digits, zero-padded.
  • Verified against the RFC 6238 Appendix B vectors for SHA-1, SHA-256 and SHA-512 at all six reference times, and RFC 4226 Appendix D HOTP vectors.
  • Base32 decoding uses the data-encoding crate with the lenient normalisation described under add.
  • otpauth URI parsing uses the url crate; the label (Issuer:account) only supplies a default issuer when the issuer query parameter is absent.

Code layout

ModuleResponsibility
main.rsParse CLI, dispatch, map CliError to exit code and stderr output.
cli.rsclap derive definitions.
commands/One file per subcommand: add.rs, code.rs, list.rs, remove.rs, skill.rs, update.rs.
totp.rsHOTP/TOTP math, Algorithm enum, expires_in.
otpauth.rsURI parsing into an AccountParams + secret.
secret.rsBase32 normalisation/decoding, Secret newtype that zeroises on drop and never implements Debug/Display.
index.rsLoad/save accounts.toml, config-dir resolution.
store.rsSecretStore trait (get, set, delete); KeyringStore and FileStore implementations; selection by env var.
error.rsCliError with exit_code().
output.rsHuman vs JSON printing.

Errors and exit codes

CodeMeaningExamples
0Success
1Internal / I/OIndex file unreadable, update download failed.
2UsageBad name, bad base32, bad URI, unknown account, duplicate without --force.
3Secret storeKeychain / Credential Manager unavailable or denied; secret missing for an indexed account.

Errors go to stderr as error: <message>, or as {"error":"<message>","exit_code":N} when --json is set. stdout stays clean so $(totp-cli code netsuite) is safe in scripts.

Testing

  • Unit: RFC vectors for HOTP/TOTP; base32 normalisation (lowercase, spaces, no padding, invalid chars); URI parsing (full, minimal, hotp rejected, label-only issuer); name validation; expires_in at period boundaries.
  • Integration (assert_cmd): each command against a temp TOTP_CLI_CONFIG_DIR with TOTP_CLI_SECRET_STORE=file: add → code (--at fixed time, known expected code) → list → remove → code fails with exit 2; duplicate add without/with --force; JSON shapes; error exit codes.
  • KeyringStore is exercised manually on macOS and Windows before the first release; it is a thin wrapper over a crate the sibling CLIs already ship.
  • CI (ci.yml, copied from netsuite-cli): cargo test --locked on macos-latest, windows-latest, ubuntu-latest; cargo fmt --check and cargo clippy -D warnings.

Repo, release, skill

  • Files: Cargo.toml, src/, tests/, skills/totp-cli/SKILL.md, README.md, .github/workflows/{ci,release}.yml, .gitignore, docs/superpowers/.
  • release.yml builds on v* tags for aarch64-apple-darwin, x86_64-apple-darwin, x86_64-pc-windows-msvc; zip assets named like netsuite-cli's so self_update finds them.
  • Dependencies: clap, keyring (apple-native, windows-native), directories, toml, serde, serde_json, thiserror, hmac, sha1, sha2, data-encoding, url, rpassword, zeroize, self_update. Dev: assert_cmd, predicates, tempfile.
  • SKILL.md: when to use, the command table, the "login asks for a 6-digit code → totp-cli code <name> --min-remaining 5" recipe, exit-code triage, and the rule that a missing account (exit 2) means ask Jon rather than guess.
  • After the first release: edit the NetSuite section of ~/.claude/CLAUDE.md to run totp-cli code netsuite --min-remaining 5 at the 2FA step, falling back to asking Jon only when the account is not enrolled. Jon enrols the NetSuite secret himself.

Out of scope for v1

  • HOTP counters, Steam-style codes, QR image decoding, import/export of whole account sets, rename, encrypted-file store on macOS/Windows, Linux credential-store backends.
